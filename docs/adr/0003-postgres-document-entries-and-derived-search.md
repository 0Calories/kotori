# Store monolingual entries as PostgreSQL JSONB documents with a derived search index

Each dictionary `Entry` permanently represents one Japanese or English expression (superseding ADR-0001, since polysemy and asymmetric `Wasei-eigo` `Origin`s do not pair one-to-one across languages) and is stored in PostgreSQL as a single `entries` row with a deterministic string ID (`jmdict:<ent_seq>`, `en:<headword>`, `kotori:<id>`), `base` JSONB for `Source` facts (`Form`s, `Sense`s, `Gloss`es, `Usage`, frequency), and nullable `enrichment` JSONB for Kotori `Enrichment` (`Caution`s, examples). Search lives in a separate, disposable `entry_search` projection rebuilt from `entries.base` (paired with TypeScript inflection/deinflection normalization, and ready for `pgvector` embeddings later), while external re-imports replace only `jmdict:` and `en:` rows and leave `kotori:` entries untouched in PostgreSQL. This gives schemaless iteration and instant `UPDATE entries SET enrichment = NULL` wipes without DDL migrations, a second database, or committed `.jsonl` compatibility shims.

## Considered Options

- **Normalized relational child tables (`forms`, `senses`, `glosses`, `examples`, `cautions`, …).** Enforces column-level SQL constraints, but forces DDL migrations, multi-table re-import diffing, and data cleanups on every `Enrichment` or `Entry` model experiment.
- **MongoDB Atlas (BSON + Atlas Search / Vector Search).** Native document model with Lucene `kuromoji` and HNSW vectors, but locks Kotori into cloud-only Atlas (~$58+/mo M10 minimum for ~350k entries + indexes), requires a heavy Docker JVM sidecar locally instead of containerless `PGlite` tests, and still needs TypeScript normalization for English irregulars/phrasal verbs, colloquial Japanese, rōmaji, and `Drafted entries`.
- **Dedicated search sidecar (Typesense / Meilisearch) alongside PostgreSQL.** Fast prefix and hybrid search, but adds a second service and live sync pipeline at single-digit MAU while built-in analyzers still miss irregular English inflections and Japanese verb lemmatization. Kept as a future escape hatch behind the search interface if needed.
